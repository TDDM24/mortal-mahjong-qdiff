## 三、几个必须对上的 Python 细节

1. **`round` 是五成双**，而且是对二进制精确值取整。`pyRound` 把 double 拆成 `整数 × 2^e`，用 BigInt
   做半偶舍入；拿 1510 个随机数 × 0~6 位小数（含 0.125、2.5 这种正好一半的）和 Python 逐位比过，
   **10570 个用例全部一致**。golden 是 `round(x, 4)` 的结果，所以 dump 时也按 4 位。
2. **浮点求和顺序**：Python 的 `sum()` 从左到右累加，JS 用 `pySum` 保证同样的顺序，否则最后几位会不同。
3. **`sorted` 的稳定性**：`top10` 按 `-diff` 排序（Python 的 sort 稳定），JS 的 `Array.sort` 现在也稳定，
   顺序和 golden 的 10 手完全一致。
4. **`act_key` 的元组**：Python 用 tuple 当字典键，JS 用 `'dahai|2m|0'` 这种字符串键。
5. **加杠**：照 `mr.py` 2026-11-18 的修正——把已有的碰升级成杠，不再记成新的一组副露
   （否则副露压力下和隐形威胁都会算错）。
6. **`safety`**：照原样，中张要**两侧都是现物**才算筋（`hit.length === sides.length`），不是常见的一侧筋。

**导出走系统保存对话框**：APK 里调用自己写的原生插件 `FileSaver`（`android/app/src/main/java/com/mahjong/record/FileSaverPlugin.java`），
用 Android 标准的 `ACTION_CREATE_DOCUMENT`（SAF）——弹系统的文件保存界面，你自己选目录和文件名，
不经过分享菜单、也不写死到某个目录，各家定制系统都能处理这个标准 Intent。浏览器里没有这个插件时退回普通下载。

### 存储为什么选 IndexedDB（而不是 Capacitor SQLite）

- 第 2 阶段要在**浏览器里就能验证**：SQLite 是原生插件，浏览器里根本跑不起来，验收会被推到装好 Android 环境之后；IndexedDB 在浏览器和 Capacitor WebView 里都能用，同一份代码。
- 数据量：单场报告 300–400 KB，一季 200 场约 60–80 MB，IndexedDB 的结构化克隆存这个量级没问题；`navigator.storage.persist()` 申请持久化，避免被系统回收。
- 备份：本来就是整套导出/导入 JSON，不依赖数据库文件本身。
- 代价：没有 SQL 查询、没有事务性的跨表能力——这个应用只有「一场一条、按时间排序」，用不上。
- 如果以后要更强的持久性和备份（比如自动云盘同步），再换 SQLite 也能只改 `db.js`（导出接口没变）。

### 两个和桌面版不同的地方（都是任务说明允许的）

1. **审计和详情都改成了卡片式**：数字和文案仍由同一套计算得出；`audit_html` / `game_html` 本身没改（第 1 阶段的逐字节比对仍然有效），手机上换成 `web/js/detailview.js` 和 `web/js/auditview.js` 的排版。

## 七、没做完 / 需要你确认

1. **`lobby`（卓）现在从报告里读**：报告里的 `split_logs[0].rule.disp`（例如「上南喰赤」）第一个字
   就是卓，`mr.reportMeta()` 已移植，所以 `--lobby` 只是备用（不给也能得到"上级"）。这点和 golden 一致。
2. **`top10` 的 `shanten`**：golden 用的是"这 14 张现在几向听"（`mr.shanten`），不是报告里自带的
   pre-draw `shanten` 字段。这两者有三手会差 1，已按 golden 的口径实现。
3. **数字格式的坑**（都已处理）：Python 的 `f'{v:.2f}'` 是五成双，`-0.0004` 会打成 `-0.00`（JS 会丢负号）；
   `str(1.0)` 是 `"1.0"` 而 JS 是 `"1"`，所以 `≤1.0` 这类显示值单独存了字符串。
4. **404 重试 3 次、间隔 2 秒**：那是 `core.compute` 里的网络行为，属于第 3 阶段（CapacitorHttp），
   计算核心里没有，到时按原样实现。
5. **APK 打包**（第 3 阶段）没做：Capacitor 工程、原生 HTTP、签名 APK 的 Windows 步骤。
6. **界面还差的部分**：搜索/筛选（桌面版「数据」页有搜索框）、长按多选、导出 Excel（任务说明明确不需要 xlsx）。
7. 手机上没有实测过点击手感；第 3 阶段装进手机后再调间距。
