# 桌面版审查要点（2026-11-27，Windows 侧更新）

这份是给 mac 审查用的。仓库里 `mahjong/desktop/` 是当前最新的桌面版源码，
比上一版（`321744d` 放进来的）只改了两个文件，其余完全一致。

## 一、相对上一版改了什么

| 文件 | 改动 | 为什么 |
|---|---|---|
| `store.py` | `add_row()` 增加**按牌谱链接去重**（+6 行） | 同一副牌谱提交两次会生成两个不同的报告 id，只按 id 去重挡不住 → 库里出现两行完全相同的场次。实测确实发生过（6 组重复）。现在先查 id，再查 `天凤牌谱` 字段是否已存在 |
| `ui/review.py` | 自动填充重写（+62 / −14） | 内嵌复盘页经常「打开后没自动粘贴链接」 |

`ui/review.py` 的具体改动：

1. **三重触发**：`loadFinished` + `loadProgress≥40` + 1.5 秒一次的看门狗定时器
   原来只靠 `loadFinished`；实测在部分 profile 配置下这个信号根本不触发，页面已渲染但填充永不执行。
2. **失败重试**：填不进去按 1/2/3… 秒递增重试，**确认填入后才停止**；原来失败一次就把 `_auto_filled` 置 True，永久放弃。
3. **强制切回「牌谱 URL」模式**：先勾 `input[name=input-method][value=log-url]` 并调用站点自己的 `changeInputMethod('log-url')`，再填值。
4. **填完 `window.scrollTo(0,0)`**：`el.focus()` 会把页面滚到下方「派遣个室」区域，用户以为页面跳错。
5. 状态栏不再回显输入框的 placeholder（那是站点自带的 2019 年示例链接，看起来像填错了）。

## 二、请重点看这几处

```
store.py:82-100      add_row 的去重逻辑（id 一次、链接一次；链接扫描是 O(n) 全表）
ui/review.py:16-52   FILL_JS（注入的 JS：选 radio、填值、滚动）
ui/review.py:79-100  _on_load / _on_progress / _auto_fill（三重触发 + 重试计数）
ui/review.py:120-140 _filled 回调（成功才置 _auto_filled，失败递增重试）
```

想验证的点：

1. 链接去重的 O(n) 扫描在几百场规模下能否接受（现在 50 场，insert 单次 < 5ms）
2. 看门狗定时器在标签关闭后会不会继续跑（`self._watch` 是 QTimer 子对象，随 tab 析构）
3. `_auto_fill` 在 `_auto_filled=True` 之后是否还有路径被触发

## 三、两个平台怎么出包

**mac**（`build_mac.sh` 已在仓库里）：

```bash
cd mahjong/desktop
bash build_mac.sh        # → dist/麻将记录.app + 麻将记录-mac.zip
```

**Windows**：PyInstaller **不能交叉编译**，Windows exe 只能在 Windows 上打：

```powershell
.venv\Scripts\python.exe -m PyInstaller --noconfirm --windowed --name 麻将记录 `
  --icon mahjong.ico --add-data "icons;icons" --hidden-import openpyxl main_qt.py
```

所以：mac 审查 + 打 .app；exe 这边我来打（源码一致，产物只是平台差异）。
