## 一、 技术栈、核心数据流与上轮修复核验简述

本项目在 `mahjong1.1` 审查包中扩展为三大子系统：**Web / Android（Capacitor Java 插件）/ macOS（Swift `WKWebView` 本地 HTTP 壳）前端与计算核心**（`02_安卓版/`，同时包含稳定版 `app-1.0.4` 与实验版 `app-1.1.0-beta2`）、**PySide6 + SQLite + OpenPyXL 桌面端**（`03_桌面版/`，含 `QWebEngineView` 内嵌 `mjai.ekyu.moe` 自动复盘页），以及**基于 50 场半庄的实证建模论文与 `pandas`/`numpy` 回归流水线**（`01_论文与数据/`）。核心数据流均由 `mr.js` / `mr.py` 回放 `mjai_log` 重建牌桌快照，与 Mortal 输出的 `review.kyokus[].entries` 逐手对齐并计算 `diff = Q(expected) - Q(actual)`（正值代表失分，`diff >= 1.0` 判定严重失误，单合法动作回合不在 `entries` 中故天然排除），进而汇总五项每百手失分指标、压力分数与六类牌效归因审计。

经逐项复核，v1.1 已有效修复首轮审计中的 **14 项历史问题**（包括：`ankan` 缺失 `pai` 崩溃、`post_call` 拍快照时机颠倒、`kakan` 重复拼入 3 张导致 6 张可见牌、牌河被鸣牌 `pop()` 误删、整手振听与第 5 张虚听漏判、`effaudit` 漏计自身副露与试摸牌可见枚数、双响放铳翻倍、终局残余立直棒归还与起家同分破平、`mac/main.swift` 吞 `bodyPrefix` 与静态目录前缀绕过、`FileSaverPlugin` 并发 `ConcurrentHashMap` 与写异常关流、`backup.js` 256 MB 解压上限、`listfilter.js` 空值转 `0`、启动脚本路径与签名口令脱敏；且 `web/` 与 `android/.../assets/public/` 保持 0 字节漂移，`test_golden.js` 全量通过）。但二次深度审计发现：**部分修复引入了新的高危回归 Bug（如赤五宽松键抢先匹配、桌面端空串引发 Excel `#VALUE!` 整行瘫痪、CSV 防注入正则可被 `=1+...` 绕过），新增模块（桌面端 `store.py` / `ui/review.py` 与论文 50 场统计脚本）及稳定版/实验版双包并存亦暴露出 16 项 P0–P3 级问题**。

### P0-1：`pickQ` / `_pick_q` 将去赤五的 `relaxed` 宽松匹配排在 `details[actual_index]` 之前，导致赤五（`5mr`/`5pr`/`5sr`）与普通 `5` 的 Q 值错配

1. **精准定位**
   - `mahjong1.1/审查包/02_安卓版/app-1.1.0-beta2/web/src/mr.js`：`actKey`（第 247–255 行）、`pickQ`（第 258–265 行）、`analyze`（第 380–390 行）
   - `mahjong1.1/审查包/02_安卓版/app-1.0.4/web/src/mr.js`：`actKey`（第 241–249 行）、`pickQ`（第 252–259 行）、`analyze`（第 368–376 行）
   - `mahjong1.1/审查包/03_桌面版/mr.py`：`act_key`（第 343–363 行）、`_pick_q`（第 366–376 行）、`analyze`（第 492–498 行）

2. **触发条件与后果**
   - 为修复首轮审计中“空切同牌丢失整手”的问题，v1.1 引入了 `actKey(a, plain)` 两级键与三级查找顺序 `exact -> relaxed -> details[actual_index]`：
     - `exact`（`plain = false`）：**保留 `tsumogiri` 摸切位、保留赤五 `'r'`、且不对副露 `consumed` 排序**；
     - `relaxed`（`plain = true`）：**一次性同时剥离了 `tsumogiri`、对 `consumed` 排序、并调用 `normTile` 抹掉了赤五 `'r'` 标记**！
   - 与此同时，`analyze()` 构建 `relaxed` 字典时使用 `if (!relaxed.has(r)) relaxed.set(r, d.q_value)`（Python 为 `relaxed.setdefault(...)`），而 Mortal 的 `details` 数组按 `q_value` **从高到低降序排列**，因此 `relaxed` 永远只保留同牌面下 **Q 值最高** 的那条候选（例如保留赤五、切普通 `5`；或用赤五副露加番）。
   - 对包内附带的 **20 份真实 Mortal 报告**进行实证扫描，共有 **456 个决策点**在同一个 `details` 列表内同时存在普通 `5` 与赤五 `5r` 且两者 `relaxed` 键完全冲突（Q 值不同）！一旦玩家实际动作因以下任一常见原因未命中 `exact`：
     1. 玩家摸牌后手切赤五 `5pr`（`actual.tsumogiri = false`），而 `details` 中仅记录摸切位不同的候选，且 `details[0]` 为切普通 `5p`（高 Q 值）、切 `5pr` 为恶手（低 Q 值）；
     2. 玩家吃/碰含 5 的搭子时，`actual.consumed` 牌序（如 `["5s", "4s"]`）与 `details` 中的 `["4s", "5s"]` 顺序不同，而候选列表中同时存在 `["4s", "5sr"]` 与 `["4s", "5s"]`；
   - `pickQ` / `_pick_q` 会在走到 Mortal 官方给出的精确下标 `details[actual_index]` **之前**先命中 `relaxed`，把普通 `5` 的高 Q 值张冠李戴赋给赤五恶手（或反之），直接抹平真实的赤五打点失分！

3. **修复方案**
   - 将标准化拆分为**保留赤五的半精确键 `semiExact`**（仅忽略 `tsumogiri` 并对保留 `'r'` 的 `consumed` 排序）与**去赤五兜底键 `relaxed`**，且优先信任通过动作类型校验的 `details[actual_index]`：
   ```javascript
   // web/src/mr.js（mr.py 的 act_key / _pick_q 同步修改）
   export function actKey(a, mode = 'exact') {
     if (!a) return '';
     const t = a.type || '';
     const mapTile = (p) => (mode === 'relaxed' ? normTile(p || '') : (p || ''));
     const pai = mapTile(a.pai);
     const rawConsumed = (a.consumed || []).map(mapTile);
     const cons = (mode === 'exact' ? rawConsumed : [...rawConsumed].sort()).join(',');
     if (mode === 'exact') return `${t}|${pai}|${cons}|${a.tsumogiri ? 1 : 0}`;
     return `${t}|${pai}|${cons}`;
   }

   function pickQ(entry, exact, semi, relaxed, details) {
     const a = entry.actual;
     const ek = actKey(a, 'exact');
     if (exact.has(ek)) return exact.get(ek);
     const sk = actKey(a, 'semi');
     if (semi.has(sk)) return semi.get(sk);
     const idx = entry.actual_index;
     if (Number.isInteger(idx) && idx >= 0 && idx < details.length && details[idx].action?.type === a?.type) {
       return details[idx].q_value;
     }
     const rk = actKey(a, 'relaxed');
     if (relaxed.has(rk)) return relaxed.get(rk);
     return null;
   }
   ```

### P0-2：新增 `'和了'` 分类漏判全部“见逃（弃和/跳过自摸）”恶手并污染牌效/防守指标，且双 APK 算法分裂、`beta2` 漏改 `VERSION`

1. **精准定位**
   - `mahjong1.1/审查包/02_安卓版/app-1.1.0-beta2/web/src/mr.js`：`decisions`（第 225–230 行）、`classify`（第 347–360 行）
   - `mahjong1.1/审查包/03_桌面版/mr.py`：`decisions`（第 326–330 行）、`classify`（第 457–473 行）
   - `mahjong1.1/审查包/02_安卓版/app-1.0.4/web/src/mr.js`：`alignKyoku`（第 265–282 行）、`classify`（第 335–346 行）
   - `mahjong1.1/审查包/02_安卓版/app-1.1.0-beta2/web/js/app.js`：`VERSION` 常量（第 15 行）、`recalcAll`（第 187–189 行）、`renderSettings`（第 598–600 行）

2. **触发条件与后果**
   - **漏判全部“见逃（Minogashi）”高额失分**：v1.1 在 `beta2` 和 `mr.py` 中新增 `'和了'` 类别时，代码写成了：
     ```javascript
     if ((entry.actual || {}).type === 'hora') return '和了';
     ```
     但日麻复盘常识是：**当玩家实际选择和牌（`actual.type === 'hora'`）时，`diff` 几乎恒为 `0`；真正产生巨额 Q 值差（单手 `diff` 常达 `2.0 ~ 4.5`）的恰恰是“见逃”（Mortal 推荐 `expected.type === 'hora'`，而玩家实际动作是跳过荣和 `actual.type === 'none'` 或跳过自摸继续切牌 `actual.type === 'dahai'` / `'ankan'`）**！
     - 此时 `actual.type !== 'hora'`，直接跳过上述判断；又因 `CALL_TYPES` 仅含 `{'chi','pon','daiminkan','ankan','kakan','none'}`（不含 `'hora'`），候选集合 `{'hora', 'none'}` 不满足 `types <= CALL_TYPES`：
       1. 若自摸见逃，或他家打出的铳牌恰好可被自家碰/吃（触发了 `dahai` 的 `canCall` 快照），该手巨额见逃失分会被直接误判进 **`'牌效'`** 或 **`'防守'`**（已在 `mr.py` 实测验证：单手 `diff = 3.3` 的荣和见逃直接使整场每百手牌效失分暴涨数分）；
       2. 若他家打出的铳牌不可吃碰，因见逃时 `mjai_log` 中根本不存在 `hora` 事件，`decisions()` 未生成任何荣和快照，该手只能靠 DP 兜底落入 `'未知'` 或错绑前后快照。
   - **双 APK 口径分裂与升级重算失效**：审查包 `02_安卓版/` 同时交付了 `mahjong-record-1.0.4.apk`（说明文档称“稳定版”）与 `mahjong-record-1.1.0-beta2.apk`。但 `app-1.0.4` 缺失“立直切牌复用同一手牌快照”和“`'和了'` 分类”两项核心改动，同一金标准报告 `0b0d6c2336b144eb` 在 `1.0.4` 下算出 `183` 决策、`每100次牌效决策 = 12.3316`，而在 `beta2` 与桌面版下算出 `184` 决策、`每100次牌效决策 = 12.0728`。更严重的是，`app-1.1.0-beta2/web/js/app.js` 第 15 行忘记更新版本号，仍硬编码为 `const VERSION = 'v1.0.4';`，导致用户从 `1.0.4` 升级安装 `1.1.0-beta2` 后，`g.calc_version !== VERSION` 判断为 `false`，设置页显示“已有 N 场是按 v1.0.4 口径算的”，不会提示用户重算，造成新旧口径数据在库内静默混杂。

3. **修复方案**
   - 在 `classify()` 中只要候选集合含 `'hora'`（即 `types.has('hora')` / `'hora' in types`）即归入 `'和了'`；在 `decisions()` 他家 `dahai` 处补充荣和听牌判定（当 `waitingTiles(st.tehai[target], ...)` 含切出牌面时同样生成 `call` 快照）；统一废弃旧口径 `1.0.4` 构建并将 `beta2` 的 `app.js` 第 15 行更新为 `const VERSION = 'v1.1.0-beta2';`：
   ```javascript
   // web/src/mr.js: classify()（mr.py 同步修改为 if 'hora' in types: return '和了'）
   function classify(entry, snap, target) {
     const details = entry.details || [];
     const types = new Set(details.map(d => (d.action || {}).type));
     if (entry.actual?.type) types.add(entry.actual.type);
     if (types.has('hora')) return '和了';
     if (!snap) return '未知';
     // ... 其余逻辑保持不变
   ```

### P0-3：桌面版 v1.1 将零防守场次改写空串 `""`，与 Excel `SUMPRODUCT` 公式相乘触发 `#VALUE!`，导致全库防守加权汇总被整格清空

1. **精准定位**
   - `mahjong1.1/审查包/03_桌面版/mr.py`：`new_workbook` 内 `wavg` 公式（第 899–900 行、第 908 行）、`build_row`（第 952 行）、`append_xlsx`（第 1011 行、第 1019 行）
   - `mahjong1.1/审查包/03_桌面版/store.py`：`export_xlsx`（第 221–222 行）

2. **触发条件与后果**
   - 为修复“零防守场次被记为 0 分（完美防守）”的问题，v1.1 在 `mr.py:build_row` 第 952 行将 `s['防守_n'] == 0` 时的 `'每100次防守决策'` 改成了 Python 空字符串 `''`，而 `store.py:export_xlsx` 第 222 行执行：
     ```python
     for r in self.all_rows():
         ws.append([r.get(h, '') for h in head])
     ```
     OpenPyXL 对空字符串 `''` 会写入**文本类型空串单元格（`data_type = 's'`，值为 `""`）**，而非真正的空单元格（`None`）。
   - 与此同时，`mr.py:new_workbook` 第 899–900 行与第 908 行生成的 Excel `汇总` 页公式为：
     ```excel
     =IFERROR(SUMPRODUCT((逐场!A2:A3000<>"")*逐场!L2:L3000*逐场!M2:M3000)/SUMPRODUCT((逐场!A2:A3000<>"")*逐场!L2:L3000), "")
     ```
     在 Excel 算术规则中，数组乘法 `0 * ""`（数值乘以文本空串 `""`，区别于乘以真正空白格 `None`）会立即求值为 **`#VALUE!` 错误**！外层 `IFERROR(..., "")` 捕获 `#VALUE!` 后直接返回空串 `""`。

   ```python

   rid = row.get('报告ID') or None

   seat = str(row.get('tw') if row.get('tw') not in (None, '') else row.get('target', ''))
   with self.lock:
       self.conn.execute('BEGIN IMMEDIATE')
       try:
           if rid:
               hit = self.conn.execute('SELECT seq FROM games WHERE id = ?', (rid,)).fetchone()
               if hit:
                   self.conn.commit()
                   return hit['seq'], True
           if link:
               for old in self.conn.execute('SELECT seq, data FROM games'):
                   d = json.loads(old['data'] or '{}')
                   old_seat = str(d.get('tw') if d.get('tw') not in (None, '') else d.get('target', ''))
                   if (d.get('天凤牌谱') or '').strip() == link and old_seat == seat:
                       self.conn.commit()
                       return old['seq'], True
           seq = self.conn.execute('SELECT COALESCE(MAX(seq), 0) + 1 FROM games').fetchone()[0]
           data = dict(row, 序号=seq)
           self.conn.execute(
               'INSERT INTO games(seq, id, added_at, data) VALUES (?, ?, ?, ?)',
               (seq, rid, datetime.now().isoformat(timespec='seconds'),
                json.dumps(data, ensure_ascii=False)),
           )
           self.conn.commit()
           return seq, False
       except Exception:
           self.conn.rollback()
           raise
   ```
