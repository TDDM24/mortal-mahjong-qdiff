# 构建与签名

三条产物的构建方式。**仓库里不含任何签名文件**，密钥要自己生成、自己保管。

---

## 1. 安卓 APK

### 1.1 生成签名（只需一次，务必备份）

```bash
cd app/android
keytool -genkey -v -keystore ../mahjong.keystore -alias mahjong \
  -keyalg RSA -keysize 2048 -validity 10000
```

再写 `app/android/keystore.properties`（已被 `.gitignore` 排除）：

```properties
storeFile=../mahjong.keystore
storePassword=你的密码
keyAlias=mahjong
keyPassword=你的密码
```

> 丢了 keystore 就无法覆盖升级（只能卸载重装、数据全丢）。建议离线备份。

### 1.2 打包

```bash
cd app
npm install                 # 或用 pnpm
npx cap sync android
cd android
./gradlew assembleRelease   # Windows 用 gradlew.bat
```

产物：`app/android/app/build/outputs/apk/release/app-release.apk`

版本号在 `app/android/app/build.gradle` 的 `versionCode` / `versionName`；
界面显示的版本在 `app/web/js/app.js` 的 `VERSION`——**两处要一起改**。

### 1.3 验证

```bash
apksigner verify --min-sdk-version 24 app-release.apk
aapt2 dump badging app-release.apk | head -1
```

---

## 2. 桌面版 exe（只能在 Windows 上打）

PyInstaller 打的是**本机**的 Python 与 PySide6 二进制，不能交叉编译。

```bat
cd desktop
pip install -r requirements.txt
build_win.bat
```

产物在 `desktop\dist\`。`dist/`、`*.exe`、`*.spec` 都已被 `.gitignore` 排除——**exe 不进仓库**，发 Releases。

## 3. macOS .app

```bash
cd desktop
bash build_mac.sh
```

---

## 4. 发版

1. 改版本号（`app/web/js/app.js` 的 `VERSION`、`build.gradle`、`desktop/core.py` 的 `VERSION`）
2. 打 APK + exe，各自验签/试运行
3. GitHub → Releases → Draft a new release，tag 写 `v1.0.0`
4. 上传 `mahjong-record-<版本>.apk` 和 `麻将记录-win.zip`
5. 正文写清这一版改了什么
