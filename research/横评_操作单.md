## 每格填什么（`横评_记录.csv`）

| 列 | 取值 | 怎么判断 |
|---|---|---|
| 覆盖(0/1) | 0 / 1 | 这一场跑出结果了填 1；报错、要付费、额度用完填 0 |
| 粒度(0/1) | 0 / 1 | 能看到**逐手**（第几巡、哪张牌）填 1；只有整场汇总填 0 |
| 可导出(0/1/2) | 0 / 1 / 2 | 0=只能截图；1=能复制文本；2=有结构化文件（JSON/CSV/表格） |
| 耗时分钟 | 数字 | 从上传到出结果，**只管人工操作时间**，不含等待 |
| 可重复 | 一致/不一致/无法测 | 同一场再跑一次，关键数字是否一样 |
| 指标个数 | 整数 | 该工具给出几个**可比较的数值**（不是形容词） |
| 段位换算(0/1) | 0 / 1 | 有没有把结果换算成段位/雀力 |
| 恶手分类(0/1) | 0 / 1 | 有没有恶手分类；标准公开才填 1 |
| 失误或恶手读数 | 数字 | **一致性分析全靠这一列**：挑该工具最接近「严重失误」的那个数，见下 |

### 「失误或恶手读数」取哪个数

| 工具 | 取这个 |
|---|---|
| Mortal | 报告里的 rating，或恶手列表条数（同一列内保持一致） |
| MAKA | 它给的「恶手/失误」计数或评分 |
| 白くん | 「真恶手率」或恶手条目数 |
| BigCoach / Gokujan | 最接近「严重失误」的那一项数值 |
| conveniencer | 导出的表格里对应列 |

**同一条工具内必须用同一个口径**，别这场用条数、下场用百分比——那算出来是我骗自己。

## 跑的顺序（按省事排）

1. **Mortal**（基准，10 场，已有 JSON，直接从库里抄 rating 和恶手条数即可）
2. **白くん**（Chrome 扩展，在 Mortal 报告页直接跑，不用重新提交 → 最快；10 场约 20 分钟）
3. **mortal conveniencer**（同样在 Mortal 报告页，看它导出的表格列）
4. **MAKA**（雀魂客户端，**5 次/天 → 分两天**；记下当天剩余次数）
5. **BigCoach / Gokujan**（要注册；看到付费墙就记 0 + 备注，别硬氪）

## 三个坑

- **MAKA 每天 5 次**：10 场要分两天，别一口气跑完 5 场才发现还有一个工具没跑
- **白くん / conveniencer 都要登录态**：先在 Chrome 里登录一次，再打开报告页
- **报告已过期那场（序号 1）**：需要先重新提交牌谱拿到新报告，否则所有依赖报告页的工具都会是 0——**这是设计好的边界测试**，如实记 0 就行
